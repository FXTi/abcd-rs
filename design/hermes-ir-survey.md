# Hermes Engine IR — Structural Survey (read-only, source-only)

All paths relative to `/Users/fxti/Work/abcd-rs/hermes-main`. `IR.h` = `include/hermes/IR/IR.h`, `Instrs.h` = `include/hermes/IR/Instrs.h`, etc.

## 1. Value model

- Single rooted class hierarchy: `Value` (IR.h:438) is the base of **everything** — instructions, literals, variables, parameters, basic blocks, functions, the module. Runtime kind is a closed `enum class ValueKind : uint8_t` (IR.h:368) generated by X-macros from `ValueKinds.def`, which encodes the full class hierarchy: `Instruction` (all opcodes from `Instrs.def`, ValueKinds.def:24-29), `Literal` → `LiteralEmpty/Undefined/Null/Number/BigInt/String/Bool/GlobalObject` (ValueKinds.def:31-41), plus `ScopeDesc`, `Variable`, `Parameter`, `BasicBlock`, `Function` → `GeneratorFunction/GeneratorInnerFunction/AsyncFunction`, `Module` (ValueKinds.def:43-56). `kindIsA` (IR.h:379) gives range-based subclass tests via `MARK_FIRST/LAST`.
- Every `Value` carries a `Type valueType` (IR.h:459) and a def-use list `UseListTy Users` = `SmallVector<Instruction*,2>` (IR.h:440,462). Note: the users list stores only the *Instruction*, not the operand index; `Value::Use` = `pair<Value*,unsigned>` (IR.h:441) is the handle used by `addUser`/`removeUse` (IR.h:504-508). `replaceAllUsesWith` exists (IR.h:511). CFG predecessors of a block are derived by scanning the block's `Users` and filtering to terminators (CFG.h:31-48).
- **SSA**: partial/latent. Instructions are SSA values (results are the instruction objects themselves, operands are `SmallVector<Value::Use,2>` at IR.h:1138), and `PhiInst` exists (Instrs.def:64; Instrs.h:2349). But IRGen output is *not* in SSA: source locals live in memory (`AllocStackInst` + `LoadStackInst`/`StoreStackInst`, Instrs.h:511-614) and closure variables in environments (`LoadFrameInst`/`StoreFrameInst`, Instrs.h:616-697). SSA is constructed by the `Mem2Reg`/`SimpleStackPromotion` passes (lib/Optimizer/Scalar/Mem2Reg.cpp, SimpleStackPromotion.cpp; pipeline at lib/Optimizer/PassManager/Pipeline.cpp:61-63,86).
- Literals are uniqued per-module via `llvh::FoldingSet` (IR.h:1966-1972; `getLiteralNumber/String/...` IR.h:2090-2099); singletons for empty/undefined/null/true/false (IR.h:1959-1964). `Parameter` holds an `Identifier` name + owning `Function` (IR.h:663-699). `GlobalObjectProperty` models declared/undeclared global vars as module-level named slots (IR.h:1089-1125, map at IR.h:1954).
- Distinction summary: instruction results = `Instruction` subclass instances; params = `Parameter`; literals = `Literal*` (typed singletons/uniqued); named variables = `Variable` (address-taken slots, accessed via load/store insts); temporaries = unnamed instruction results / `AllocStackInst` slots (named only by an embedded `Label`, Instrs.h:515-522).

## 2. Variable/scope model

- `ScopeDesc` (IR.h:561-660) is itself a `Value`: a tree of lexical scopes (`parent_`, `innerScopes_`, `createInnerScope()` IR.h:580), owning a list of `Variable*` (IR.h:609,657), optionally bound to a `Function` (IR.h:655,2261) and a `SerializedScope` for lazy/debug info (IR.h:628,396-417). `dynamic_` flag marks `eval`-tainted scopes (IR.h:637).
- `Variable` (IR.h:1009-1086) = name (`Identifier`), `DeclKind` (var/let/const, IR.h:1018), owning `ScopeDesc*` (IR.h:1024), TDZ semantics `getObeysTDZ()` = non-`var` (IR.h:1063), strict-const flag (IR.h:1067). Variables are *named memory locations*, not SSA values.
- Runtime environments are first-class SSA values: `CreateScopeInst(ScopeDesc)` (Instrs.h:699) and `CreateInnerScopeInst(parentScope, ScopeDesc)` (Instrs.h:725) materialize the environment; `NestedScopeCreationInst::getParentScope()` (Instrs.h:138) is the static "get parent scope" link — it's a def-use edge to the parent `ScopeCreationInst`, not a runtime call. Closures: `CreateFunctionInst(Function *code, ScopeCreationInst *env)` (Instrs.h:758-808), result typed `Closure` (IR.h:768). Variable access: `LoadFrameInst(Variable, env)` / `StoreFrameInst(value, Variable, env)` (Instrs.h:616,655); post-lowering HBC forms use resolved indices: `HBCLoadFromEnvironmentInst(env, Variable)` / `HBCStoreToEnvironmentInst(env, value, Variable)` (Instrs.h:2598,2639), `HBCCreateEnvironmentInst`/`HBCResolveEnvironment` (Instrs.def:32-33).
- Registers vs variables: no register model in IR — locals are stack slots (`AllocStackInst` with an embedded `Label` name, Instrs.h:511) until Mem2Reg/StackPromotion promote them; the mapping named-variable ↔ slot is by construction of IRGen, and `FunctionScopeAnalysis` computes lexical depth per `ScopeDesc` (Analysis.h:133-180). Global vars split into `GlobalObjectProperty` (addressable) and stack/SSA when promotable.

## 3. Instruction set flavor (Instrs.def)

Closed opcode set, class-per-opcode, operands stored as flat `Value*` list with per-class `enum {...Idx}` accessors. Categories:

- **Scope/env**: `ScopeCreationInst` family (Instrs.def:28-42); last operand is always the `ScopeDesc` (Instrs.h:80-84).
- **Memory/locals**: `AllocStackInst`, `LoadStackInst`, `StoreStackInst`, `LoadFrameInst`, `StoreFrameInst` (Instrs.def:50,82-85).
- **Property access**: `LoadPropertyInst(object, property)` / `StorePropertyInst(value, object, property)` (Instrs.h:1449,1156) — the property operand is a general `Value` (computed keys supported); static names appear as `LiteralString`. Specialized: `TryLoad/TryStoreGlobalPropertyInst` (property forced to `LiteralString`, Instrs.h:1210-1249,1490-1527), `StoreOwnPropertyInst`/`StoreNewOwnPropertyInst` (literal key + `isEnumerable` bool, Instrs.h:1251-1349), `StoreGetterSetterInst` (Instrs.h:1351), `DeletePropertyInst` (Instrs.h:1412). So: both literal-name and computed forms, same opcode, distinguished by operand kind.
- **Calls**: `CallInst` operand layout `{Callee, NewTarget, This, args...}` (Instrs.h:842-876; `this` is "argument 0"); optional `textifiedCallee` `LiteralString` for error messages (Instrs.h:818-855). `ConstructInst` (result typed Object, Instrs.h:909-947), `CallBuiltinInst` (callee = `LiteralNumber` builtin index, Instrs.h:951-992), `HBCCallDirectInst/HBCCallNInst/HBCConstructInst` (Instrs.def:137-141), `GetBuiltinClosureInst` (Instrs.h:994).
- **Object/array creation**: `AllocObjectInst(size, parentObject)` typed Object, side-effect None (Instrs.h:1529-1567), `AllocArrayInst(sizeHint, elements...)` (Instrs.h:1628), `HBCAllocObjectFromBufferInst` with literal key/value pairs (Instrs.h:1569), `CreateRegExpInst`, `CreateArgumentsInst` (Instrs.def:88,92).
- **Arithmetic/logic**: single `UnaryOperatorInst`/`BinaryOperatorInst` with an `OpKind` enum field (all JS operators incl. `in`, `instanceof`, short-circuit-assign; Instrs.h:1760-1930) — *not* per-operator opcodes. Side effect computed from operand *types* (`getBinarySideEffect`, Instrs.h:1911-1929). Conversions: `AsNumber/AsNumeric/AsInt32/AddEmptyString/CoerceThisNS` (Instrs.def:46-53).
- **Control flow**: terminators `BranchInst`, `CondBranchInst`, `SwitchInst` (literal cases, Instrs.h:1995), `SwitchImmInst`, `CompareBranchInst`, `ReturnInst`, `ThrowInst`, `UnreachableInst`, plus loop-for-in terminators `GetPNamesInst`/`GetNextPNameInst` (Instrs.h:2045-2204; these write results through address operands, cf. `getChangedOperandsImpl` Instrs.h:2088-2094).
- **Exceptions**: `TryStartInst`, `TryEndInst`, `CatchInst`, `ThrowInst` (see §7).
- **Generators/async**: `SaveAndYieldInst(result, nextBlock)` terminator (Instrs.h:2758), `StartGeneratorInst`, `ResumeGeneratorInst` (Instrs.h:3456,3481), `CreateGeneratorInst`; function flavors `GeneratorFunction`/`GeneratorInnerFunction`/`AsyncFunction` (IR.h:1815-1903). Iterators: `IteratorBegin/Next/Close` (Instrs.def:96-98).
- **Misc**: `MovInst`/`ImplicitMovInst`, `PhiInst`, `DirectEvalInst`, `DebuggerInst`, `GetNewTargetInst`, `ThrowIfEmptyInst` (TDZ), `HBC*` backend layer.

## 4. Side-effect system

- Lattice `SideEffectKind {None, MayRead, MayWrite, Unknown}` (IR.h:356-366), semantics documented in doc/IR.md:99-120 ("write" = read-and/or-write; `Unknown` additionally = may throw / IO). Allocation-only instructions are `None` (IR.md:115-120).
- **Hand-written per instruction class**: each class in Instrs.h defines a `getSideEffect()` method; a giant X-macro switch `Instruction::getDerivedSideEffect()` dispatches on `ValueKind` (lib/IR/IR.cpp:424-433). Not opcode-table-driven. Completeness is total — the switch covers every `DEF_VALUE` by construction. `BinaryOperatorInst`/`UnaryOperatorInst` refine by operand types (Instrs.h:1911). A parallel hand-written mechanism `getChangedOperands()` → `WordBitSet` marks operands written through (out-params), e.g. `GetPNamesInst` (Instrs.h:2088), dispatched at IR.cpp:435-445. Convenience predicates `mayReadMemory/mayWriteMemory/mayExecute` (IR.h:1224-1240).
- Consumers: DCE (lib/Optimizer/Scalar/DCE.cpp:49-56 — kills non-terminators with no users unless `mayWriteMemory`), InstSimplify and Mem2Reg (grep: InstSimplify.cpp, Mem2Reg.cpp), CodeMotion/loop hoisting per IR.md:110-114. Effect granularity is coarse: no distinction of *which* memory (heap vs frame vs stack slot), and property/call instructions are all `Unknown` (e.g. `LoadPropertyInst` Instrs.h:1477-1479, `CallInst` Instrs.h:896-898).

## 5. CFG and analysis infrastructure

- CFG.h: hand-rolled `pred_iterator` (over block's user list, CFG.h:26-83) and llvh `SuccIterator` over terminators (CFG.h:136-177); `GraphTraits` for `BasicBlock`/`Function` incl. inverse (CFG.h:186-262); `DominanceInfo` = llvh `DominatorTreeBase<BasicBlock,false>` with instruction-level `properlyDominates` (CFG.h:278-293). No post-dominators.
- Analysis.h: `PostOrderAnalysis` (custom because catch blocks are unreachable from entry, Analysis.h:20-25), `LoopAnalysis` (headers/preheaders, Analysis.h:99-128), `FunctionScopeAnalysis` (scope depths, Analysis.h:133), `DomTreeDFS` visitor framework (Analysis.h:184-286).
- Passes (lib/Optimizer/Scalar): DCE, CSE, CodeMotion, SimplifyCFG, InstSimplify, Mem2Reg, StackPromotion/SimpleStackPromotion, TypeInference, Inlining, FuncSigOpts, TDZDedup, HoistStartGenerator, ResolveStaticRequire, ScopeTransformations (ScopeMerger), Auditor, plus `SimpleCallGraphProvider` and `InstructionEscapeAnalysis`. Full pipeline order: lib/Optimizer/PassManager/Pipeline.cpp:43-103.
- Closest-to-dataflow/taint pieces: `Auditor` + `Term.h` build a **constraint graph** with terms for lambdas/calls/objects/arrays/property load/store/escapes (include/hermes/Optimizer/Scalar/Term.h:16-60,41-42) — a flow-insensitive, unification-style points-to-ish analysis used for Wasm-safety auditing, not a general taint framework. `InstructionEscapeAnalysis` is narrow (single-block escape prefixes, InstructionEscapeAnalysis.h:56). No generic dataflow solver, no taint pass.

## 6. Type system

- `Type` (IR.h:51-350) is a **bitmask lattice** over JS type kinds: Empty(TDZ)/Undefined/Null/Boolean/String/Number/BigInt/Object/Closure/RegExp (IR.h:53-67), plus a sub-mask for Number: Double/Int32/Uint32 (IR.h:69-75,121-125). Union/intersect/subtract are bitwise (IR.h:134-146). No object shapes, no prototypes, no string values, no arrays as a kind (AllocArray result is just `Object`, Instrs.h:1640).
- Attached directly to every `Value` (`setType`/`getType`, IR.h:528-535); constructors set precise types for literals and typed instructions (e.g. IR.h:923-929, Instrs.h:768,937,1546).
- Inference: `TypeInference` module pass (lib/Optimizer/Scalar/TypeInference.cpp) — local rules per instruction propagating the bitmask (e.g. binary-op result typing TypeInference.cpp:299-372), phi merging via union (TypeInference.cpp:270-283); run 3× in the pipeline (Pipeline.cpp:59,78,89). Types are trusted for optimization: `BinaryOperatorInst::getBinarySideEffect` uses operand types to downgrade effects (Instrs.h:1911-1929), enabling CSE/DCE; `isSideEffectFree(Type)` (Instrs.h:30). It's a may-analysis (union = widening), sound for that use but too coarse for provenance.

## 7. Exceptions

- Dedicated instructions + explicit CFG edges, no landing pads. `TryStartInst` is a **terminator with two successors**: catch-target block and try-body block (Instrs.h:2278-2325; catch listed first so post-order lays out try first, Instrs.h:2282-2284). `CatchInst` (no operands) is the first instruction of the catch block and *produces* the caught value (Instrs.h:1932). `TryEndInst` marks region end (Instrs.h:2327). `ThrowInst` is a terminator with **zero successors** (Instrs.h:1954-1993) — the exceptional edge is implicit via the enclosing TryStart, not an edge from each potentially-throwing instruction. Consequence: may-throw points are only visible via `SideEffectKind::Unknown` + the try-region structure; catch blocks may be unreachable from entry (Analysis.h:20-24).

## 8. Serialization / round-trip

- There **is** a documented textual IR format (doc/IR.md, incl. syntax and per-instruction "Arguments/Effects" sections) and printers: `Instruction::dump`, `BasicBlock::dump`, `Function::dump`, `Module::dump`, `Type::print` (lib/IR/IR.cpp:265,270,689,757,816). 
- There is **no parser/round-trip**: no IR text reader exists in lib/include/tools (no `IRParser`/`parseIR` anywhere); the format is dump-only for debugging (`hermes -dump-ir`).
- Verification: `verifyModule(Module, OS, VerificationMode{IR_VALID, IR_OPTIMIZED})` (include/hermes/IR/IRVerifier.h:20-37) — a no-op outside debug builds (IRVerifier.h:31-33). Implementation is an `InstructionVisitor`-based `Verifier` (lib/IR/IRVerifier.cpp:36) that walks module/scopes/functions/blocks (IRVerifier.cpp:134-260) checking structural invariants per opcode (`visit##XX` per DEF_VALUE, IRVerifier.cpp:96), e.g. operand kinds and CFG well-formedness.

## 9. Strengths/weaknesses for a taint-analysis consumer

**Has:**
- Clean closed-world class-per-opcode IR with exact operand indices, types on every value, and maintained def-use (`Users`) lists — cheap backward slicing from sinks (IR.h:462, Instrs.h operand enums).
- SSA after Mem2Reg + `PhiInst`; explicit scope/environment model (`Variable`, `ScopeDesc`, env SSA values) makes closure capture flows traceable through `LoadFrame/StoreFrame` operand edges (Instrs.h:616,655).
- Dominators/loops/GraphTraits and pass infrastructure ready to host a new analysis; per-class visitor (`IRVisitor.h`) and verifier for validation.
- Property name often statically available as `LiteralString` operand (field names for access paths, Instrs.h:1466,1215).

**Lacks (FlowDroid-style needs):**
- **No access paths / no field sensitivity in the effect or type system**: `LoadPropertyInst`/`StorePropertyInst` are `Unknown` effect; "memory" is a single monolithic location in `SideEffectKind` — no per-field or per-object read/write sets (IR.h:356-366, Instrs.h:1197,1477).
- **Weak call graph**: `SimpleCallGraphProvider` is explicitly local def-use only, "no closure analysis" (SimpleCallGraphProvider.h:17-27); dynamic dispatch, getters/setters, `eval` (`DirectEvalInst`), and `Unknown`-effect calls make sound interprocedural taint hard. `CallInst` has callee/this/args operands, but callee is usually an opaque value.
- **No source/sink annotation machinery** and no taint/provenance lattice; the `Type` bitmask can't carry taint and is co-designed for codegen legality, not security.
- **Exceptions as implicit edges**: taint through thrown values requires reconstructing try-region membership (only `TryStart`/`Catch` markers; `ThrowInst` has no successor edge, Instrs.h:1984).
- **No IR round-trip/serialization**: an external tool must consume the C++ API (or bytecode, a different layer), not a text/bitcode IR (§8).
- Computed property keys and monomorphic `Object` type erase field information (no shapes/hidden classes in IR), so access-path reconstruction is heuristic; `Term.h`'s constraint graph (Term.h:16-33) is the only existing skeleton one could extend for property-level flow, and it is flow-insensitive and Wasm-audit-specific.
- Post-lowering (HBC) instructions change variable access to index-based env ops (Instrs.h:2598-2670), so a consumer must pick a pipeline stage: pre-lowering IR (named `Variable`s, cleaner semantics) is the right cut point.
