# ISA Layer Design (abcd-isa-sys / abcd-isa)

## Three-layer structure

```
isa.yaml (268 instructions / 332 opcodes / 4 prefix groups, vendored from upstream)
        │  Ruby codegen (gen.rb + isapi.rb + pandafile_isapi.rb, ERB)
        ▼
Generated C++ headers (opcode/format/flags enums, operand-decode inlines, emitter declarations)
        │  cc compilation (isa_bridge.cpp + vendored bytecode_emitter.cpp)
        ▼
C bridge (isa_bridge.h: decode/classification/version/stateful emitter)
        │  bindgen
        ▼
abcd-isa-sys (bindings.rs + the Bytecode enum generated by bytecode.rs.erb)
        │  safe wrappers
        ▼
abcd-isa (decode / encode / Version)
```

## Code generation

The data source `vendor/isa/isa.yaml` is byte-identical to upstream and locked by the vendor-sync system (see vendor-sync.md). `build.rs` drives 7 templates with Ruby:

| Template | Output |
|----------|--------|
| `bytecode_instruction_enum_gen.h.erb` | Opcode/Format/Flags/Exceptions enums |
| `bytecode_instruction-inl_gen.h.erb` | Operand decoding and classification inlines (~11.5k lines) |
| `bytecode_emitter_{def,gen}_gen.h.erb` | Emitter method declarations/implementations |
| `file_format_version.h.erb` | Version constants + API mapping |
| `isa_bridge_emit_dispatch.h.erb` (ours) | opcode → emitter-method dispatch switch |
| `bytecode.rs.erb` (ours) | Rust `Bytecode` enum + constructors + decoding |

**Key design of our templates** (`bytecode.rs.erb`):

- The `Bytecode` enum is grouped **by mnemonic**, not by opcode: `Mov` merges MOV_V4_V4 / MOV_V8_V8 / MOV_V16_V16, with typed operands (`Reg`/`Imm`/`EntityId`/`Label`).
- `representative_opcode()`: the largest format of each group stands in for FFI classification calls (all opcodes in a group share properties, so the exact value does not matter).
- Jump immediates resolve to `Label` (**instruction index**, not byte offset) after decoding; `set_label` / `jump_label_arg_index` support rewriting.
- The `insn::*` module generates typed constructors per mnemonic (`insn::Jeq::new(Reg(0), Label(2))`).

## Decoding (abcd-isa/src/decoder.rs)

Two passes:

1. **Linear scan**: read opcode → look up size → `Bytecode::decode_one` extracts operands; raw relative offsets of jumps are stashed. Prefix bytes (≥ 251) make a 2-byte opcode; truncation is detected.
2. **Jump resolution**: for each jump, `insn_offset + raw_imm` yields the target byte offset; `binary_search` snaps it to an instruction boundary and stores `Label(target_index)`. Off-boundary targets report `InvalidJumpTarget`.

## Encoding (abcd-isa/src/emitter.rs)

- `Label` semantics are **instruction indices** into the input slice (identical to decode output — round-trip is idempotent).
- Two-stage mapping: collect all jump targets → allocate one C++ emitter label per target; emit in order, binding labels at targets, and substitute C++ label ids into jump operands.
- The C++ `BytecodeEmitter::Build()` owns format selection and long-jump widening (imm8→imm16→jCC inversion + far jump); Rust never predicts encodings. After emission, the actual bytes are re-scanned to derive per-instruction offsets (needed by try-block metadata).

## Classification and versions

- Classification: `is_jump / can_throw / is_terminator / is_return_or_throw / is_suspend / is_range / is_throw_ex / has_flag`. Opcode-level queries construct a zero-filled buffer to avoid depending on operand bytes.
- Versions: `Version` (a 4-tuple) provides `current()` (24.0.0.0), `min_supported()`, `for_api()`, `is_in_supported_range()`, `is_blocked()` (incompatible blocklist), delegating to the vendored `file_format_version` implementation — no hand-copied data.

## Design principles

1. **Encode only, never decide**: `abcd-isa` does not know semantic gates like "SuperCallOpt is only available on API 18+"; opcode selection is IR lowering's job.
2. **Data and code share one source**: ISA facts live only in isa.yaml; both the Rust and C++ sides are generated from it, with zero hand-written mirrors.
3. **Minimal FFI boundary**: the bridge only forwards thinly (`Inst::GetFormat` etc.); decoding logic stays in vendored generated code.
